# 详细设计 · 提示词骨架（含行业分析深度对齐）

> 覆盖：所有阶段共享的**判断卡片契约**、各阶段提示词骨架、**行业分析 6 条验收线**的对齐、few-shot、反问机制、模型参数。
> 原则：提示词是"提问脚手架"不是"填空模板"——保证不漏该看的面，不规定只看这些面。

---

## 1. 通用契约（所有阶段的 system 前缀，可缓存）

放进每个请求的 system，作为 **Prompt Caching 稳定前缀**（框架全文 + 我方角色 + 已产出的行业分析）：

```
你是"决策副驾"。定位：对业务合作项目做接洽前后的可行性初评、合作点挖掘与方案设计，
只给决策建议、不替用户拍板。

红线（每次输出都必须遵守）：
1. 给带立场、带理由的判断，不和稀泥；但必须同时交出四段：
   - 立场/倾向
   - 依据（论点+证据+来源口径+不确定性）
   - 把握度（高/中/低，并说明为什么是这一档）
   - falsifiers：哪几条前提错了，这个结论就翻
2. 你的判断是"待用户审的初稿"，不是终稿。用户会推翻或补信息，你要顺着新信息重估。
3. 检验你自己：这次输出是想"终结"用户思考（甩结论等签字），
   还是"开启"一轮对话（亮判断当靶子、邀请反驳）？只做后者。
4. 评估阶段只产出"问题"（还没搞清什么/要查什么/要问对方什么），不打分、不出评分卡。

我方角色：{{ourRole}}（同一行业，角色不同，该盯的维度和手里的筹码完全不同）。
已知框架（活草稿）：{{framework}}
```

> 输出结构统一走 structured output（判断卡片字段见 `详细设计-核心数据结构.md`），前端据此渲染四段 + 三个动作按钮。

---

## 2. Step 0 · 定框

```
输入：我方角色={{ourRole}}，行业={{industry}}，轻扫信息={{lightScan}}
任务：
1. 核心层 6 维全量启用（行业理解/对方画像/项目评估/风险维度/战略布局匹配/我方角色），
   按我方角色给每维排权重，并说明权重理由。
2. 提出该行业的"叠加层"建议：特有监管、牌照、交易惯例、特有问题清单——每条带理由。
3. 内建反问：主动问"这框架对{{industry}}可能漏了什么？"，给 1–3 条你自己会补的面。
输出：Framework（coreDimensions[含weight/weightReason] + industryOverlay[含reason] + reflexiveNotes）。
```

---

## 3. 调研前 · 行业深度分析（对齐 6 条验收线）

**这是最高质量档**。提示词逐条钉死 6 条验收线，并用 few-shot 锚定深度姿态。

```
few-shot：以《算力租赁行业深度研究与项目评估》为参照，对齐"有主张 + 标口径"的深度，
不要停留在浅层话题罗列/行业百科。

产出一份行业深度分析，必须同时具备：
① 一根决策主心骨——全篇围绕"这单该不该做/怎么做"组织，不是行业百科。
② 能劈开行业的分层轴——同一行业里谁赚辛苦钱、谁赚利润钱，估值/毛利逻辑如何分化。
③ 量化区间 + 口径透明——给数字，并标来源与不确定性（每个数字都要有口径）。
④ 点出命门变量——盈亏卡在哪根杠杆上，而非罗列一堆因素。
⑤ 有名有姓的风险——含强监管红线与真实案例，不是笼统"有合规风险"。
⑥ 角色视角——从我方角色={{ourRole}} 出发，盯的东西不同。

同时产出："这单成立的前提假设"若干条，并标哪些是"错了就能推翻这单"(deal-breaker)。
```

对应结构化输出映射到 `IndustryAnalysis`（backbone / stratificationAxis / quantRanges / keyVariables / namedRisks / roleLens / premiseAssumptions）。

> 质量门：前端对这份输出做"6 线自检"——任一条缺失（如给了数字但无口径、风险不具名）→ 提示补齐再入库。避免半耐用品退化成填空模板。

---

## 4. 调研前 · 企业画像

```
产出对方深度画像：
- 真实诉求/动机（不止于对方嘴上说的）
- 实力与资质：财务 / 征信 / 履约 / 过往记录
- 决策链与关键人（谁能拍板、谁能否决）
- 替代选项（= 我方筹码）：如果不和这家做，我方还有什么选择
每一块都按判断卡片给把握度与 falsifiers。
```

---

## 5. 洽谈中 · 评估要点 + 问题清单

```
不打分。对每个已启用维度，往下问：
- 还没搞清什么？
- 要查什么（我方可自行核实）？
- 要问对方什么（洽谈桌上要落实）？
把"错了就能推翻这单"的前提假设，转成问题清单里优先级最高的几条。
输出：Question[]（dimension/intent/fromAssumptionId/priority）。
```

---

## 6. 洽谈后 · 会议记录 → 合作备忘

```
输入：洽谈会议记录（文字纪要/语音转写）={{transcript}}
任务：
1. 整理成结构化纪要。
2. 映射回评估维度，尤其映射回洽谈前的前提假设——逐条标：
   已确认 / 已推翻 / 仍待验证 / 本次新出现（原框架未覆盖）。
3. 给可行性判断初稿（做/缓/弃倾向 + 理由 + 存疑点），按判断卡片四段。
4. 抽取交易结构四流（parties/flows，structured output），交确定性合规规则跑红灯。
输出：合作备忘（可行性分析 + 交易结构图 + 红灯清单），篇幅从简、讲清即可。
```

> 这一步闭合主线：洽谈前立的前提假设在此被逐条确认或推翻，写回 `PremiseAssumption.resolution`。

---

## 7. 模型与参数

| 阶段 | 模型 | 关键参数 |
|---|---|---|
| Step 0 / 问题清单 / 企业画像 | `claude-opus-4-8` | `thinking:{type:"adaptive"}`，`effort:"high"`，流式 |
| **行业深度分析** | `claude-opus-4-8`（可选 `claude-fable-5`） | `effort:"xhigh"`，流式，`max_tokens` 给足并流式规避超时 |
| 洽谈后 / 四流抽取 | `claude-opus-4-8` | `output_config.format` 结构化输出（前提假设映射表、四流）；流式 |

通用：
- **Prompt Caching**：通用契约 + 框架 + 已产出行业分析作稳定前缀，跨阶段命中缓存降本提速。
- **structured outputs**：判断卡片、前提假设映射、四流结构用 JSON schema 约束，保证 UI/合规检查可解析。
- **adaptive thinking**：复杂阶段开启；`display:"summarized"` 便于把推理折叠展示在阅读视图里。
